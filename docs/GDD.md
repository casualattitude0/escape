# Escape — 遊戲設計文件（GDD）

一場不對稱的貓鼠追逃：一群研究人員圍捕，一隻編號怪物逃脫。

---

## 1. 世界觀

某個秘密收容設施中，一隻被列管的 **SCP 編號怪物** 掙脫了收容。警報響起，設施封鎖。

- **編號怪物**（Runner）只有一個念頭：在被重新收容前，找到出口逃離設施。
- **研究人員**（Hunter）必須在有限的視野與空間中，重新捕獲這隻怪物。

設施本身是舞台：明亮受控的房間、狹窄的維修**管道（Tunnel）**、以及散落各處、用來開門的關鍵物件。

---

## 2. 角色與陣營

| 陣營 | 角色 | 人數 | 目標 |
|------|------|------|------|
| 追捕方 | 研究人員 **Hunter** | 2 ~ 4 | 重新捕獲 Runner |
| 逃脫方 | 編號怪物 **Runner** | 1 | 蒐集物件、開門逃脫 |

不對稱設計：**多名 Hunter 對抗單一 Runner**。Runner 更靈活、能鑽管道、能反擊；Hunter 靠人數與圍堵取勝。

---

## 3. 勝負條件

**限時一分半（90 秒）**，倒數歸零就結算。

**Runner 獲勝**
- 把 **3 把鑰匙**全部裝到**同一扇逃脫門**上（門上三個記號全亮）→ 開門逃脫。

**Hunter 獲勝**
- **撐過 90 秒**：時間到、Runner 還沒開門 → Hunter 陣營勝利。
- Hunter **不靠「抓死」取勝**——壓制成功只是把 Runner 手上正在搬的鑰匙**打散**、逼他重跑一趟（見 4.1 / 4.5），本質是**拖時間**。

---

## 4. 核心玩法

### 4.0 核心循環（純粹版）

把所有裝飾拿掉，這遊戲無法再簡化的一句話：

> **Runner 在 90 秒內把 3 把鑰匙一把一把搬上同一扇門；搬運時最脆弱 → 聲音讓 Hunter 聚攏 → 包夾壓制、把 Runner 手上的鑰匙打散、燒他的時間；Runner 用「有限的擊殺」與「管道位移」拆散包夾，護送鑰匙到門。**

這條循環決定了每個系統的存在理由，設計與調校都以「不破壞它」為最高原則：

| 系統 | 在循環中的角色 |
|------|----------------|
| 鑰匙搬運（4.1） | Runner 唯一的推進手段，也是**唯一的主要「可被壓制窗口」** → 推進與暴露天生綁定 |
| 90 秒倒數（3.） | 給整場一個單向壓力；每次被打散＝燒時間，讓 Hunter「拖延」本身就是進攻 |
| 受限視野（4.2） | 逼 Hunter 分散 → **單人抓不到** |
| 聲音（4.3） | 唯一把分散的 Hunter 重新聚攏的機制 → 聲音的意義不是「被看到」，而是「被**包夾**」 |
| 連打拔河壓制（4.5） | 需要 **2+ 人**才有威脅 → 壓制成功＝**打散 Runner 手上的鑰匙**、逼他重跑；Runner 怕的是「一群」而非「一個」 |
| 反擊 / 管道（4.4） | 拆包夾的**位移/節奏工具**、護送鑰匙的手段，不是消滅對手 |
| 無限復活（4.5） | 讓「殺 Hunter」無法成為勝利手段，只能換時間與空間 |

**核心張力設計原則**：
- **1 個 Hunter 逼近** → Runner 能反擊逼退、能逃（單人抓不到是刻意的）。
- **2+ Hunter 包夾** → 捕獲條推進快過 Runner 的掙脫 → Runner 必須製造距離，否則被抓滿、手上鑰匙被打散。
- 因此每次交手的本質是：**Runner 搬著鑰匙的這段路，Hunter 能不能靠聲音聚成一群、在 Runner 把鑰匙送到門之前把捕獲條連打滿、逼他重跑。**

> ⚠️ **要避免的兩種壞結果**：壓制是**連打拔河**（見 4.5）—— Hunter 連打填「捕獲條」、Runner 連打填「掙脫條」，捕獲條滿＝打散 Runner 手上的鑰匙。① **太黏**：單人也能輕易打散、或掙脫太弱 → Runner 永遠送不到門、90 秒必輸 → 挫折。② **太鬆**：掙脫太強 + 打散無感 → 抓到也白抓、Runner 一路平推 → Hunter 無事可做。四個關鍵旋鈕（**掙脫倍率與捕獲條存檔、2 人門檻、重生代價、可被壓制窗口**）就是把「每次包夾」調成「有結算但不必然」——理想是**多數單人包夾攔不住、雙人包夾多半能打散一次**。見 4.4 / 4.5。

### 4.1 逃脫門與鑰匙搬運

**目標結構**

- 地圖上有 **3 扇逃脫門**，彼此拉開距離。每扇門有 **3 個記號（鑰匙槽）**，顯示這扇門的裝鑰匙進度。
- 地圖上散落 **3 把鑰匙**，**不分種類、可互換**。Runner 一次只能**搬一把**。
- 逃脫流程：撿起鑰匙 → **搬到任一扇門** → 裝上（點亮該門一個記號）→ 重複，直到**同一扇門**集滿 3 個記號 → 開門逃脫，Runner 勝。

**只需完成一扇門（門的選擇）**

- 三扇門＝**三條逃脫路線的選擇**，只要任一扇集滿即可。
- 但**鑰匙要集中在同一扇**：裝上的記號留在該門、不會移動；把鑰匙分散裝到不同門只會拖慢自己。**選哪扇門主攻、何時改換**是 Runner 的核心決策（門的暴露程度、離鑰匙／管道遠近、Hunter 守在哪都要算）。

**搬運＝主要暴露窗口（取代舊的蒐集定身）**

- **手上有鑰匙時**，Runner 進入**「可被壓制」狀態**：移動略慢、持續發聲（上小地圖／附近視野變清晰，見 4.3），並成為 Hunter 唯一值得壓制的目標。
- **空手時**最靈活、幾乎抓不住 —— 所以 Hunter 的重點不是盲追，而是**守鑰匙、守門、在 Runner 搬運那段路上包夾**。
- 於是「推進逃脫」與「變脆弱」天生綁在一起：這段搬運路，就是原型要驗證的核心攻防窗口（把舊版「拿一下就走」的一瞬窗口，換成「送一整趟」的長窗口）。

**被抓 → 鑰匙被打散（本設計的核心張力）**

- 搬鑰匙途中若被 Hunter **壓制成功**（捕獲條滿，見 4.5）→ 手上那把鑰匙**隨機傳送到地圖另一處重新出現**，Runner 被釋放（短暫暈眩）。
- **已裝在門上的記號不受影響** —— 裝上就安全、進度不倒退；被打散的只有**當下手上那一把**。
- 打散＝雙重損失：**丟了鑰匙的位置**（要重新找、重新搬）＋ **燒掉 90 秒裡的寶貴時間**。這就是 Hunter「拖時間取勝」的主要手段。

**HUD 箭頭（指引）**

- Runner 畫面恆有**箭頭指向逃脫門**，標示門的位置與各門進度。
- 用意：Runner 永遠知道「往哪送」，把心力放在**「怎麼安全送到」**而非迷路找門；被打散後也能立刻重新定位。

**升壓棘輪（沿用 4.3 精神）**

- **每點亮一個記號，Runner 的暴露永久提高一階**（輪廓更亮／小地圖提示更頻／「附近」判定半徑更大）。
- 裝得越多 → 越接近逃脫 → 越藏不住，配合 90 秒倒數，終局單向走向高潮。

### 4.2 Hunter 的受限視野

- Hunter 的視野是**受限的**（例如：視錐 / 迷霧 / 有限照明），無法一眼看穿整張地圖。
- 這讓單槍匹馬的 Hunter 難以獨自鎖定 Runner，鼓勵**分頭搜索、互相通報、包夾**。

### 4.3 聲音機制（Runner 的風險與代價）

Runner 的許多行動都會**發出聲音**，例如：

- 鑽進 / 鑽出**管道（Tunnel）**
- 拾取、使用道具
- （其他劇烈動作）

聲音會依 Hunter 與 Runner 的相對位置產生不同後果：

| Hunter 位置 | 後果 |
|-------------|------|
| **在 Runner 附近** | Hunter 的視野變得**明顯清晰**，更容易直接看見 Runner |
| **在其他房間** | Runner 位置**在小地圖上出現提示**，指引 Hunter 前來 |

→ 每一次蒐集、每一次鑽管道，都是「加速逃脫」與「暴露自己」之間的取捨。

#### 升壓棘輪（讓張力單向升高）

- **每蒐集一件物件，Runner 的暴露永久提高一階**（例如：怪物輪廓發光更亮、或小地圖提示頻率變高、或「附近」判定半徑變大）。
- 蒐集越多 → 越接近逃脫 → 越藏不住 → **終局自然變熱**，局勢單向走向高潮。
- 這不新增系統，只是把「聲音暴露」接上「蒐集進度」，用最少的東西製造 5. 節所要的高潮。

### 4.4 Runner 的行動手段

- **管道滑行（Tunnel Slide）**：Runner 鑽進管道快速移動、擺脫追捕、抄捷徑（詳見下方）。
- **反擊（Attack）**：Runner 可對附近 Hunter **簡易攻擊並擊殺**，逼退圍捕、爭取空間與時間。
  - **在壓制之外使用**：一旦進入連打拔河（被抓住），Runner 的攻擊鍵改為「掙脫連打」（4.5），**不能**再靠攻擊直接掙脫 —— 拔河模型下，掙脫是拚捕獲條 vs 掙脫條，不是殺人。
  - **建議加冷卻（關鍵旋鈕）**：擊殺後短暫冷卻，避免 Runner 站原地把整群 Hunter 一次清空、讓包夾永遠成不了形。有冷卻後：能逼退 1~2 人爭取脫離，但無法瞬間清場，被殺的 Hunter 又要吃重生代價（4.5）回不來。

#### 管道滑行（Slide）細節

**基本行為**

- Runner 進入管道口後，會**自動觸發滑行**、沿管道方向直線高速滑過去，直到抵達另一端出口。
- 滑行過程中**不能左右轉向**：一旦進入，路線就此鎖定 —— 選錯入口就會被送到不想去的出口。因此「進哪條管道」是一個要事先判斷的決策，而非過程中臨時修正。
- 滑行速度明顯快於徒步，是 Runner 拉開距離、抄捷徑、跨區蒐集的核心機動手段。

**進入 / 移動 / 脫出**

- **進入**：需走到管道口並觸發；起手有短暫的鑽入動作（可被 Hunter 看見去向）。
- **移動**：滑行是**強制、不可中途取消**的位移，途中 Runner 無法攻擊、蒐集或轉向；分岔管道（若有）的方向在**入口就決定**，不是滑行中選。
- **脫出**：抵達出口時，Runner 有一小段**出管硬直**（起身/落地），此時最脆弱 —— 若 Hunter 守在出口，正是壓制的好時機（呼應 4.5 觸發條件）。

**代價與風險（呼應 4.3 聲音機制）**

- 鑽入與鑽出管道都會**發出聲音** → Hunter 在附近則視野變清晰、在他房則小地圖提示。
- 路線鎖定 + 出口固定 → 管道是雙面刃：走得快，但**出口可被預判與埋伏**。老練的 Hunter 會記住管道網、守株待兔。

**與 Hunter 的互動**

- Hunter **通常無法進入管道**（體型/設定所致），只能繞路或守出口 → 管道是 Runner 專屬的機動優勢。
- 因此圍捕的關鍵之一是**封鎖出口 + 收容裝置佈署在出管落點**，把「出管硬直」轉化為壓制機會。

### 4.5 捕獲手段（連打拔河壓制）

原型的捕獲是一場**連打拔河**（實作：`GrappleSystem`）：Hunter 貼身開場後，Hunter 連打填「**捕獲條**」、Runner 連打填「**掙脫條**」，誰先填滿誰贏這一回合。收容裝置是後期才補的變化層，原型先不做（見 8. 原型範圍）。

#### 連打拔河（主要捕獲動作）

- Hunter 貼近**可被壓制**的 Runner 並按捕獲鍵 → 開始一場拔河。
- 每次 Hunter 連打 → **捕獲條 +**；每次 Runner 連打 → **掙脫條 +**（Runner 單擊值較高，例如 2x）；兩條都會隨時間**衰退**。
- **捕獲條滿 → 壓制成功**：Runner 手上的鑰匙被打散（隨機重生到地圖另一處，見 4.1）＋ Runner 短暫暈眩後被釋放。**不是本局結束** —— 本局只由 90 秒倒數結算。
- **掙脫條滿 → Runner 掙脫**、脫離拔河，鑰匙保住。
- Runner 一旦離開 Hunter 的判定範圍，拔河**中止**。
- **空手被壓制**：沒有鑰匙可打散，只造成短暫暈眩（時間／位置損失），因此 Hunter 只在 Runner **搬鑰匙時**壓制才划算。

**四個關鍵旋鈕（讓每次包夾都有結算）**

1. **掙脫倍率 + 捕獲條存檔**：Runner 單擊 vs Hunter 單擊的比值（現值 2:1），以及捕獲條是否有 **ratchet 存檔**（現值：達 checkpoint 後不掉回 0）。
   - ⚠️ 存檔 + 無 2 人門檻 → **單一 Hunter 反覆抓也能慢慢累積攻頂**，違反「單人抓不到」。原型建議：**削弱或移除存檔**，或把存檔綁在「2 人門檻」達成後才生效。
2. **2 人門檻**：設計目標**單人幾乎無法填滿捕獲條**（讓包夾成為唯一解）。手段擇一：(a) 單人時捕獲條增速極低 / 衰退極快；或 (b) **需 2 名 Hunter 同時貼身，捕獲條才會累積**。多人時再加速（2 人 ≈ 2x）。
3. **重生代價**：見下方「無限復活與重生點」。
4. **可被壓制窗口**：見下方「觸發條件」。

##### 觸發條件（可被壓制窗口）

拔河不是隨時能開，Runner 必須處於**可被壓制狀態**（實作：`capturable`）。原型的窗口由主到次：

- **搬運鑰匙（主要窗口）**：手上有鑰匙的**整段路** Runner 都可被壓制（見 4.1）→ 這是 Hunter 最主要、也最有意義的抓捕機會（抓到才有鑰匙可打散）。把舊版「拿一下就走」的一瞬窗口，換成「送一整趟」的長窗口 —— **這正是先前「追半天沒結算、不好玩」的解方**。
- **出管硬直**：剛鑽出管道的起身空檔（現值 0.5s）。
- **自行靜止**：Runner 速度極慢（現值 ≤ 55）時。
- **空手（次要）**：壓制只造成暈眩、無鑰匙可散，Hunter 通常不划算。
- 滿足時，Runner 身上與 Hunter 端應有**「可壓制」提示**（高亮 / icon）。

##### Hunter 端操作流程

1. **開場**：貼近可被壓制的 Runner、按捕獲鍵 → 拔河開始。
2. **連打**：持續連打累積捕獲條；Runner 脫離判定範圍或衰退則進度下滑。
3. **包夾**：第二名 Hunter 靠近同一目標一起連打 → 捕獲條加速（跨過 2 人門檻）。
4. **完成**：捕獲條滿 → 打散 Runner 手上的鑰匙（重生到他處）、Runner 暈眩被釋放；Hunter 買到時間，回頭守門／守鑰匙繼續拖。

##### Runner 被壓制後的操作（掙脫）

被壓制不是即死，Runner 有一段**掙脫窗口**：

- **連打掙脫（主要解法）**：連打攻擊鍵填掙脫條（單擊值較高）→ 填滿即甩開拔河、恢復行動。
- **反擊逼退隊友**：拔河**外**的 Hunter（尚未加入拔河的）仍可被 Runner 反擊逼退（4.4）→ 阻止第二人加入、避免跨過 2 人門檻。
- **被多人壓制的困境**：2+ 人同時連打 → 捕獲條快過掙脫條 → Runner 必須在填滿前**製造距離或逼退對方**，凸顯「別被包夾」。
- **掙脫代價**：拔河期間 Runner 無法移動與蒐集，本身就是時間損失。

##### 角色動畫與狀態表現

| 狀態 | Hunter 表現 | Runner 表現 |
|------|-------------|-------------|
| 進入判定 | 準心/目標高亮「可壓制」 | 身體輪廓高亮提示 |
| 壓制起手 | 前撲 / 架住的抓取動作，腳步鎖定 | 被架住、掙扎的受制姿態 |
| 壓制維持 | 環形讀條圍繞 Runner，多人時讀條變色/加粗 | 掙扎循環動畫，讀條隨進度上升 |
| Runner 反擊 | 被擊殺 → 擊倒/消散演出，讀條碎裂中斷 | 甩開 → 反擊動作 → 恢復自由移動 |
| 讀條讀滿 | 奪下鑰匙 / 甩開的動作 | 鑰匙脫手（飛散演出）→ 短暫踉蹌後恢復 |

- **讀條位置**建議環繞在 Runner 身上（而非 Hunter），讓場上所有玩家都能一眼看出「有人快被抓了」，製造援救與逃脫的共同張力。
- **音效**同步：起手一個明確咬合聲、維持期低頻讀條聲、中斷時碎裂聲、完成時收容確認聲 —— 也和 4.3 的聲音暴露主題呼應。

#### 收容裝置（把 Runner 逼進讀條）

- Hunter 可在場上**佈署收容裝置**（電網 / 力場 / 麻醉噴口），佈署需要時間、數量有上限。
- 裝置範圍會**遲滯或困住** Runner（減速 / 短暫定身），製造 Hunter 上前讀條的空檔。
- Runner 可**破壞裝置**，但破壞需花時間並**發出聲音**（呼應 4.3 的暴露風險）。
- 捕獲流程因此變成兩層配合：**趕（往裝置逼） → 讀（貼身壓制）**，需要多名 Hunter 分工（誰佈署、誰驅趕、誰讀條）。

#### 無限復活與重生點（把「擊殺」變成 Runner 的節奏貨幣）

原則不變：Hunter **無限復活**，Runner 無法靠殺光 Hunter 取勝。但「無限復活」不等於「免費復活」—— 若重生毫無代價，Runner 最爽的一招（反擊擊殺）價值歸零，捕獲三角僵局化（見 4.0）。因此擊殺不「永久移除」Hunter，而是用**時間 + 空間**換節奏：

- **倒地而非瞬間重生（關鍵旋鈕）**：Hunter 被擊殺後進入短暫倒地/消散（約 1~2 秒）才重生。這 1~2 秒 Hunter 退出戰鬥，就是 Runner 買到的時間。
- **固定重生點放在地圖邊緣 / 中央樞紐（關鍵旋鈕）**：重生點**遠離逃脫門與蒐集點**。被殺的 Hunter 必須重新跑回戰場，回程距離＝Runner 買到的路線。
  - 具體規則（原型先用最簡單版）：被殺 → 在**最近的、非其原本追擊方向**的重生節點復活；或直接統一回中央樞紐。
  - 重生點**絕不靠近目標**，否則等於獎勵卡點與自殺守門。
- **擊殺＝節奏貨幣**：配合 4.4 的反擊冷卻，一次擊殺換到「幾秒 + 一條路線」，而不是換到「少一個對手」。這才對得起「無限復活」這個設定。
- Hunter 仍可**用命換位置與時間**（送死擋路、卡逃脫門），但因為有倒地延遲與回程距離，送死不再零成本，避免無腦自殺卡門。

### 4.6 地圖設計原則

重生點放哪，就是地圖的心跳；地圖是核心循環的舞台，設計圍繞「聚攏—包夾—拆散」展開：

- **沒有死路**：死路對 Runner ＝即死，對追逃遊戲是設計事故。用**環路 + 高密度交叉口**，讓每次追逐都有「往左往右」的即時決策。
- **鑰匙散佈與門分置四方**：鑰匙初始（及被打散後）落點與門拉開，逼 Runner 長距離搬運、製造聲音、暴露路線 —— 搬運本身就是暴露的代價。
- **3 扇逃脫門彼此拉開距離**：讓 Hunter 無法一人守多門；配合「壓制需 2+ 人」，單人守門很弱，天然防自殺卡門。門也是鑰匙的「目的地」，守門＝守 Runner 的必經終點。
- **管道**：入口分散、做成 Runner 專屬圖層；**出口可被預判/埋伏**（呼應 4.4），是雙面刃。
- **重生節點置於邊緣 / 中央樞紐，遠離目標**（呼應 4.5）：讓「回程距離」成為擊殺的價值來源。
- **視野管理**：配合 4.2 受限視野，用房間（開闊、易被看穿）與走廊（狹窄、易被堵）的節奏，製造搜索與伏擊的空間差。

## 5. 節奏與張力

- **一分半（90 秒）的短時限**是整場的心跳：Runner 要在極短時間內完成 3 趟成功的搬運，Hunter 只要拖住就贏 —— 每一次「打散」都直接換算成勝利進度。節奏天生高壓、單向升溫。
- Runner：在「快速搬運推進」與「保持安靜不被包夾」之間權衡；靠管道與反擊護送鑰匙、拆包夾。
- Hunter：受限視野下必須**協同搜索**，守門、守鑰匙、在 Runner 搬運那段路包夾；就算被擊殺也能靠人數與復活持續施壓、繼續拖時間。
- 隨著門上記號越點越多，逃脫越近、暴露越高、時間越少 —— 局勢自然走向高潮。

## 8. 原型範圍（先砍什麼）

擔心「純粹」，答案是**做減法**。GDD 已經很滿，先驗證核心循環（4.0）好不好玩、四個旋鈕調不調得動，原型階段**先延後**以下，避免系統互相干擾到分不出是哪裡不好玩：

| 先砍 / 延後 | 原因 | 原型替代 |
|-------------|------|----------|
| 收容裝置（電網/力場/麻醉） | 整套「趕→讀」第二層系統 | 先只驗證「聲音→包夾→群體讀條」單靠走位是否成立 |
| 三種物件 x/y/z | 差異化是後期調味 | 3 把可互換鑰匙、搬上同一扇門的 3 個記號 |
| 連打掙扎 QTE | 與反擊功能重疊 | 反擊冷卻當唯一掙脫手段 |

**原型的唯一問題**：在最小地圖（一個環路 + 幾條管道 + 3 扇門 + 3 把鑰匙）上，2~3 個 Hunter 對 1 個 Runner，90 秒倒數、Runner 搬鑰匙上門、被壓制就打散 —— 靠聲音聚攏、群體讀條、反擊+管道護送 —— **90 秒內 3 趟搬運的攻防夠不夠緊張、會不會一面倒？** 這題答對了，再往上疊裝置與差異化。
